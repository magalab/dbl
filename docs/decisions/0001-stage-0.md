# ADR 0001: 阶段 0 技术验证

- 状态：进行中
- 日期：2026-10-25

## 决策

- UI 使用 `github.com/egoist/mygo` 的 `ui` 原生绘制 API，不引入 WebView 或前端构建链。
- MyGo 固定为 `v0.6.2`。该版本的模块声明要求 Go `1.27.1`，当前开发机安装 Go `1.27.3`。
- 首个真实数据源选择 SQLite，固定采用 `modernc.org/sqlite v1.61.0` 纯 Go 驱动，以维持 `CGO_ENABLED=0`。
- SQL 结果先采用可取消的行流/受控批次读取，不做通用 SQL 自动分页改写。
- UI 结果窗口使用固定容量环形缓冲，默认最多 10,000 行、约 64 MiB 估算行数据；每批结果读取以约 8 MiB 字节量为目标，单行超过窗口上限时跳过并在 UI 计数提示。追加行时覆盖最旧行，不在每批结果到达时搬移整张窗口。自然顺序直接使用逻辑行号，只有用户开启排序时才分配排序索引。
- SQLite schema 对象按 `type,name` keyset 每次读取最多 200 项，左侧使用 MyGo 虚拟列表；不在连接时预取整库对象元数据。
- 后台工作完成后通过 MyGo `Window.Update` 回到 UI 线程更新状态。
- 连接、对象、查询、导出及文件面板失败时，状态栏只显示简短摘要；消息区提供按需展开的技术错误详情，取消与超时仍显示专门状态。
- 菜单使用原生 `mygo.App.SetMenu` 与平台角色菜单，查询执行提供 `CmdOrCtrl+Return` 快捷键；菜单回调只启动异步工作，不直接等待数据库操作。
- 结果表单元格右键菜单使用 MyGo `ui.Element.ContextMenu` 和 `mygo.Clipboard.WriteText`，复制时对整行按 TSV 规则转义，便于粘贴到表格软件。
- 结果表按 MyGo `ListState.Sort` 和可排序列头实现本地排序；排序建立在最多 10,000 行的保留窗口上，只生成稳定行索引，不更改游标来源顺序。续读追加后重新计算顺序，来源行范围仍按原查询顺序解释。
- 排序比较器对同类型和混合整数/浮点数使用无分配的数值比较；跨整数与浮点采用边界安全的精确比较，避免把大整数先转成 `float64` 丢失精度。
- 本地文本排序使用 Go 字符串顺序，BLOB 按字节顺序；不会复现 SQLite 自定义/区域 collation。需要数据库排序语义时应在 SQL 中显式写 `ORDER BY`。

## 依据与待验证事项

- MyGo 官方文档说明 native UI 使用 Go 的 `ui` 包绘制；macOS 使用 Metal，Windows 使用 Direct3D 11，Linux 使用 OpenGL。文档列出代码编辑器、虚拟 List/Table、可拖动 Split、输入法支持和后台状态更新 API。
- 版本锁定：`github.com/egoist/mygo v0.6.2`。引用：[官方 v0.6.2 go.mod](https://raw.githubusercontent.com/egoist/mygo/v0.6.2/go.mod)。
- 文档引用：[Native UI](https://mygo.egoist.dev/docs/ui)、[Views](https://mygo.egoist.dev/docs/ui/views)、[Code editor](https://mygo.egoist.dev/docs/ui/code-editor)、[Table](https://mygo.egoist.dev/docs/ui/table)、[Split view](https://mygo.egoist.dev/docs/ui/split)。
- 菜单 API 依据：[MyGo 菜单栏文档](https://mygo.egoist.dev/docs/menus)；`App.SetMenu`、`MenuItem.Click`、角色菜单和 accelerator 也在锁定版本 [v0.6.2 API](https://pkg.go.dev/github.com/egoist/mygo@v0.6.2) 中提供。原生菜单尚待桌面运行验证。
- SQLite 文件选择使用锁定版本 `mygo.Dialog.Open` / `mygo.Dialog.Save` 系统对话框，并从独立 goroutine 调用，避免阻塞 UI 事件处理；[v0.6.2 Dialog API](https://pkg.go.dev/github.com/egoist/mygo@v0.6.2#DialogModule)。实际 macOS 文件面板行为待桌面运行验证。
- 结果表交互依据：[MyGo v0.6.2 UI API](https://pkg.go.dev/github.com/egoist/mygo@v0.6.2/ui) 中的 `Element.ContextMenu`，以及[剪贴板 API](https://mygo.egoist.dev/docs/native)。复制菜单尚待桌面运行验证。
- 排序交互依据：[MyGo Table 排序文档](https://mygo.egoist.dev/docs/ui/table#sorting)说明 `ListState.Sort` 驱动可排序列头，应用负责按 `SortOrder` 排列行并通过 `Key` 保持行身份。排序仅用于当前保留窗口，尚待桌面运行验证。
- MyGo 无障碍名称、标题层级、选中状态和状态播报依据：[Accessibility 文档](https://mygo.egoist.dev/docs/ui/accessibility)及 [v0.6.2 UI API](https://pkg.go.dev/github.com/egoist/mygo@v0.6.2/ui)。
- SQLite 驱动：`modernc.org/sqlite v1.61.0`，官方包资料说明这是 CGo-free 的 SQLite 移植；模块 `go.mod` 要求 Go 1.26.0，与当前 Go 1.27.3 兼容。驱动 go.mod 要求 `modernc.org/libc v1.79.0`，下游需保持相同版本，因此已显式锁定为间接依赖。包许可证为 BSD-3-Clause，随包分发的 SQLite 本体为 public domain。Go runtime 的六目标许可证并集已写入根目录 `THIRD_PARTY_NOTICES.md`，SQLite/libc 上游第三方通知已纳入 MyGo 资源并通过 macOS bundle 文件校验；DBL 自身许可证和非 Go 资产许可仍需发布审阅。引用：[v1.61.0 包文档](https://pkg.go.dev/modernc.org/sqlite@v1.61.0)、[v1.61.0 go.mod](https://raw.githubusercontent.com/modernc-org/sqlite/v1.61.0/go.mod)。
- 采用 pure Go SQLite 驱动以满足 `CGO_ENABLED=0` 与跨平台目标。Apple M1 / macOS 15.8.1 / Go 1.27.3 的真实 modernc 驱动扫描基准中，10,000 行 × 128 字节、批次 128/512/1,024 分别约 3.22/3.03/3.04 ms、397.9/421.8/421.5 MB/s、2.09/2.11/2.11 MB 分配。该数据只代表此机器和此工作负载，不等同于用户查询端到端体验，也不作为跨驱动性能结论。
- upstream v1.61.0 包文档公布了 Linux/amd64 CPU 时间对比（Go 1.27、`modernc.org/libc v1.75.7`）：无索引 `ORDER BY ... LIMIT` 为 C SQLite 的 2.0 倍、`GROUP BY` 聚合为 1.9 倍、带文本比较的相关子查询为 1.3 倍。这是上游特定硬件/依赖组合的参考值，不是本项目 `libc v1.79.0` 或 macOS arm64 的实测结论；本项目仍需运行自己的扫描基准。引用：[modernc SQLite v1.61.0 性能说明](https://pkg.go.dev/modernc.org/sqlite@v1.61.0#hdr-Performance)。
- SQLite DSN 使用转义后的 `file:` URI 和明确 `mode=ro/rw`；新建文件先以 `0600` 权限独占创建，避免误把错误路径当成新库。读取对象使用 `sqlite_schema`，按页加载；读取列使用安全引用的 `PRAGMA table_xinfo`，覆盖隐藏列和生成列。
- 连接工作区提供只读打开开关；只读连接池的每个物理连接通过 SQLite authorizer 限制写操作、`ATTACH` 和非只读 PRAGMA，并保留 schema 浏览需要的元数据 PRAGMA。SQLite URI `mode=ro` 同时保护主数据库文件。连接可异步关闭，先取消查询游标，再关闭 `database/sql` handle。
- SQLite `database/sql` 连接池限制为最多 4 个打开连接、1 个空闲连接，避免每个连接独立持有 page cache/libc 状态而无界增长；上游文档也建议显式限制连接池大小。
- 纯 Go 驱动取消文件型 SQLite 查询时可能丢弃被中断的底层连接；应用关闭已取消游标，连接池可为下一条查询建立新连接。相应真实驱动回归用例已通过。参考：[modernc SQLite v1.61.0 变更记录](https://gitlab.com/cznic/sqlite/-/blob/v1.61.0/CHANGELOG.md)。
- 完整 CSV/JSON 导出在独立只读连接上重新执行生成当前结果窗口的 SQL（不读取用户后来编辑的文本），按批次直接写文件，不累计全量结果；使用 `O_EXCL` 和 `0600`，拒绝覆盖已有文件。只读连接池通过 SQLite authorizer 限制写操作、`ATTACH`、`DETACH`、非只读 `PRAGMA`、`load_extension`、`readfile` 和 `writefile`；普通只读表达式及 schema 元数据查询可用。文件 I/O 函数不属于 SQLite 核心函数，但仍显式拒绝，以防未来构建注册相关扩展；主库 `mode=ro` 单独不足以阻止对附加库写入。重新执行意味着非确定性 SQL 或并发数据变更可能让导出结果与当前窗口快照不同，UI 在按钮旁明确说明此行为。JSON 将文本类型的 UTF-8 字节切片转成字符串，其他 `[]byte` 以标准 JSON Base64 表示；CSV 对 BLOB/BINARY/BYTEA 类型或无效 UTF-8 字节加 `base64:` 前缀编码；CSV 将 SQL NULL 写为空单元格。
- SQL 历史按工作区保留进程内最近 100 条，可单独清空；默认不写磁盘。用户明确启用本机持久化后，最多保存 100 条且单条最多 64 KiB，关闭持久化会清除已保存历史。详情与持久化隐私约束见 ADR 0002。
- 依赖源码和校验和现已由当前 Go 模块缓存与 `go.sum` 提供；完整应用纯 Go 构建、真实 SQLite 集成测试、race 和 vet 已运行通过。代理仍不可用时，可用 `GOPROXY=off` 在缓存完整的环境重现这些检查。
- Go 环境：Go 1.27.3，`darwin/arm64`，默认 `CGO_ENABLED=1`。阶段构建应显式以 `CGO_ENABLED=0` 验证。
- 首发平台候选与构建矩阵：

  | 目标 | 最低系统/架构 | 构建方式 | 当前证据 |
  |---|---|---|---|
  | macOS（首发候选） | macOS 12+，arm64；MyGo 打包默认最低版本为 12.0 | `CGO_ENABLED=0 go run .`；本机二进制 `CGO_ENABLED=0 go build -o build/dbl .` | 开发主机 macOS 15.8.1 arm64；app bundle 窗口显示、文件面板、查询和 CSV 导出已实际验证；darwin/amd64 交叉构建通过 |
  | Linux（验证目标） | x64、arm64；原生 UI 运行需 GTK 3 | `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build ./...`；arm64 替换 `GOARCH` | 完整应用 amd64/arm64 交叉构建通过；未在 GTK 3 主机启动 |
  | Windows（验证目标） | Windows 10/11，x64、arm64 | `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build ./...`；arm64 替换 `GOARCH` | 完整应用 amd64/arm64 交叉构建通过；未在 Windows 主机启动 |

  MyGo 文档列出上述原生 UI 平台，并说明 macOS 12+、Linux x64/arm64 与 Windows 10/11 x64/arm64；modernc v1.61.0 也列出 darwin arm64/amd64、linux arm64/amd64 和 windows arm64/amd64 支持。交叉构建不代表目标平台运行验收，也不是正式支持承诺。引用：[MyGo 平台与要求](https://mygo.egoist.dev/docs)、[打包默认最低 macOS 版本](https://mygo.egoist.dev/docs/distribution)、[modernc v1.61.0 支持平台及性能说明](https://pkg.go.dev/modernc.org/sqlite@v1.61.0#hdr-Supported_platforms_and_architectures)。
